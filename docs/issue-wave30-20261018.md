# Executable actor safety/liveness proof obligations — draft 2026-10-18

Issue #6: a sequential model reporting PASS does not prove concurrent actor safety or progress.

## Model and fairness
- State transitions include mailbox reservation, publish, dequeue, application turn, cancellation, trusted CONTROL, restart and bounded fault injection.
- Model checking must explore adversarial schedules rather than one sequence; explicitly bound actors, messages, queue capacity and elapsed logical steps.
- Safety: no duplicate finalization; no actor turn uses freed/alien state; queue credit never negative/over capacity; stale actor incarnations never grant ownership; CONTROL authority never forged.
- Liveness under stated fairness: a runnable admitted DATA item eventually completes or produces terminal error unless actor dies; trusted CONTROL remains schedulable under saturated DATA.
- Distinguish conditional liveness from unconditional real-world timing guarantees.

## Counterexample seeds
1. Queue full, CONTROL termination arrives during DATA send.
2. Restart between dequeue and terminal receipt; stale recipient handle must not accept new message.
3. Cancellation coincides with reservation refund; refund exactly once.
4. Source callback synchronously reenters actor while critical state loan held; no deadlock/alias.
5. Two carrier threads execute distinct turns with RW state loans; mutable exclusivity preserved.

**Required evidence:** enumerated schedules, model hash, counterexamples/coverage, compiler/backend SHA and actual source execution. A green sequential test is never labeled formal concurrency proof.

**Status:** formal proof charter, not an executed model-checker run.
